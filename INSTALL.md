# Install

Two ways: let your coding agent do it (recommended), or do it by hand in about ten minutes.

## A. With your coding agent

Open your agent in the repo you want to enable and paste:

```text
Install the ADLC kit in this repository.
1. Clone https://github.com/stLalo/adlc-kit next to this repo if it is not on this machine yet.
2. Read AGENTS.md and docs/install/AGENT_INSTALL.md in that clone and follow them exactly.
Start with the read-only discovery, write ADLC_ADAPTATION_PLAN.md, and stop for my approval before you install anything.
```

What happens:

1. **Discovery, read-only.** The agent finds your code host, CI, branch protection, coding agents and models, spec tool, secret manager and deploy commands.
2. **A plan.** It writes `ADLC_ADAPTATION_PLAN.md` in your repo: for each part of the kit, use a shipped adapter, write one, or skip it, and what you lose when you skip.
3. **Your approval.** Nothing is installed before you say yes. Change the plan freely: it is yours.
4. **Install and prove.** It runs the installer, writes any adapters the plan calls for, and runs the tests.
5. **Server-side protection.** It walks you through protecting your main branch. That step is yours: an agent should not hold that permission.

Works with any agent that can read files and run shell commands. If yours cannot run commands, use B and let it read the docs.

## B. By hand

```bash
git clone https://github.com/stLalo/adlc-kit ~/tools/adlc-kit        # anywhere outside your repo
bash ~/tools/adlc-kit/tests/run.sh                                    # offline self-test, about 30 s

~/tools/adlc-kit/core/scripts/install-repo.sh /path/to/your/repo \
    --harness claude-code      # or: codex | git-hooks | several, comma separated
                               # --spec openspec|plain   --judge codex|claude|human   --host github
```

Then:

1. **Edit `.adlc/config.env`** in your repo: `TEST_CMD`, the judge, the role models, deploy commands. Every key is explained in the file.
2. **Check machine-local settings** in `<kit>/.adlc/kit.env`: protected branches, agent identity. Defaults work.
3. **Commit through a pull request**: `.adlc/config.env`, `docs/sessions/INDEX.md`, `AGENTS.md`, `.gitignore`, and the harness files (`.claude/commands`, `.claude/agents`, `CLAUDE.md` for Claude Code). The kit reads config from your main branch, so nothing works until this is merged.
4. **Protect the main branch** on your host: [docs/server-gate.md](docs/server-gate.md).
5. **Try it**: restart your agent in the repo and run `/sessions`, then `/intent <repo> "something small"`.

What the installer writes: [docs/adapting.md](docs/adapting.md#what-the-installer-writes). It creates no symlinks and never overwrites your config.

## Update

```bash
git -C ~/tools/adlc-kit pull
~/tools/adlc-kit/core/scripts/install-repo.sh /path/to/your/repo --harness <same as before>
```

The second line regenerates harness files from the new playbooks. Read [CHANGELOG.md](CHANGELOG.md) first: before 1.0, minor versions can change config keys.

## Uninstall

Delete from your repo: `.adlc/`, the block between `<!-- adlc-kit:begin -->` and `<!-- adlc-kit:end -->` in `AGENTS.md`, generated files in `.claude/commands` and `.claude/agents` (they carry a "Generated by adlc-kit" line), the kit entries in `.claude/settings.local.json`, and `.git/hooks/pre-push` if it names adlc-kit. Your `docs/sessions/` and specs are yours to keep.
